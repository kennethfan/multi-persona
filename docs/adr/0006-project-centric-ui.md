# 0006 以项目为核心的界面组织

- Status：accepted
- Date：2026-10-14

## Context

T4 做出的界面是平铺式标签页条 + 双容器分屏，用户验证中暴露两个问题：项目（旧称容器）多了之后标签栏会混成一锅粥；
站内新窗口（`target=_blank`、Google 登录弹窗）跳出应用外——根因是 `<webview>` 的 `new-window`
事件在 Electron 22 已被移除，拦截代码是死代码。需要以项目为核心重新组织界面，并把弹窗收进应用内。

## Decision

- 项目 1:1 会话单元，即容器改名：一个项目 = 一个会话分区（`persist:mp-<id>` 不变），项目内任意站点/标签/弹窗共享同一会话；不同账号即不同项目。
- 布局：左侧竖栏为项目列表（颜色点 + 名），顶部标签条只显示当前项目的页。
- “站点”不建模为正式概念：标签页只有 URL + 标题 + 所属项目；域名/favicon 仅做展示。
- 分屏保留并解耦：任意两个标签页可并排，不限是否同项目。
- 弹窗一律收进应用内浮层（modal），与打开它的页面共享会话；可多层叠加，按打开顺序盖，关闭时自动刷新打开它的标签页。
- 数据迁移：启动时一次性 `containers.json` → `projects.json`，id 与分区名不变，会话零丢失。

## Consequences

- T4 的 renderer（标签条 + 分屏）需要返工，主界面按“项目栏 + 当前项目标签条”重写。
- 新窗口拦截改用主进程 `did-attach-webview` + `setWindowOpenHandler`（deny 原生窗口，经 IPC 转界面层开标签/弹窗）；渲染进程需向主进程注册 webview 与项目的配对。
- 弹窗进标签/modal 后，强依赖 `window.opener` 回调的登录流程仍有失败可能，同分区共享会话可缓解，个案处理。
