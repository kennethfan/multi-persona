# 0007 实例作为会话单元

- Status：accepted
- Date：2026-10-14

## Context

0006 确立了"项目 1:1 会话单元"。用户给出真实场景：一个"视频"项目下同时开 5 个实例，
每个实例登录一个账号，实例间互不干扰。这推翻了 0006 的核心决定：隔离单元必须从项目
下沉到实例，项目退化为 pure 分组。

## Decision

- 实例成为新的会话单元：每个实例独立会话分区（`persist:mp-<实例id>`），同实例内多标签/弹窗共享同一套数据存储。
- 项目只做分组：存名字 + 实例列表，不对应任何分区。
- 布局：左栏两级树（项目可折叠，下挂实例），顶部标签条只显示当前实例的页。
- 管理语义平移：实例的新建/改名/改色/删除照搬原项目 CRUD，删除二次确认 + 清该实例会话。
- 迁移：现有 `projects.json` 中每个项目自动包一层（变成含 1 个默认实例的分组），id 与分区语义延续，会话零丢失。
- T6 提醒语义延续：同一站点账号出现在任意两个实例即提醒，不分是否同项目。
- 弹窗机制（0006 seam ④：modal、可叠层、关闭刷 opener）原样延续，归属由"当前项目"改为"当前实例"。

## Consequences

- 0006 被部分取代：项目 1:1 会话、左栏项目列表、分区命名 `persist:mp-<项目id>` 不再成立；0006 的弹窗与分屏思路保留。
- 已写的 `projects.ts` / `project-store.ts` / T4 重做代码需要返工：存储与分区键下沉到实例。
- 同项目下双实例是正常操作（5 个视频账号），不再视为误操作；真正的误操作信号只剩"同账号进两个实例"。
